📦 Procurement Module

IncapttaPro Procurement

Full-lifecycle procurement management — from purchase requests through goods receipt, 3-way invoice matching, and integrated finance payment processing.

🗂 6 modules
📄 14 pages / routes
🗄 5 Firestore collections
🔐 7 role levels
Stack: Vue 3.5 · Firebase 11 · Pinia

Goods Receipt Notes — receive and post to inventory
3WM
3-Way Invoice Matching — GRN × PO × Invoice
PMT
Payment Processing — wired into Finance ledger
💡 The procurement workflow is fully sequential: PR → PO → GRN → Invoice → Payment. Each stage is gated by the previous. Payments write directly into the existing operationalExpenses ledger — no separate collection is created.

Store Pattern

The store uses early-return guards on all fetch*() functions to prevent duplicate listeners:

function fetchSupplierInvoices() {
  if (invoicesUnsubscribe) return   // Guard — already listening
  loadingInvoices.value = true

  invoicesUnsubscribe = onSnapshot(
    query(collection(db, 'procurementSupplierInvoices'), orderBy('createdAt', 'desc')),
    (snap) => { supplierInvoices.value = snap.docs.map(d => ({ id: d.id, ...d.data() })) }
  )
}

All write functions (add*, update*) use dynamic Firestore imports to reduce initial bundle size:

const { collection, addDoc, serverTimestamp } =
  await import('firebase/firestore')

All listeners are cleaned up by cleanupListeners() which is called on store disposal.

💳 Payment Processing

Process Payment View
GET /procurement/invoices/:id/payment

Processes payment for an APPROVED invoice and integrates directly with the Finance module's accounts ledger. Only accessible to ACCOUNTANT, ADMIN, SUPER_ADMIN — MANAGER is explicitly excluded from this route.

Payment Processing Steps

StepActionCollection / Store Call
1 Create operational expense record financeStore.recordExpense(data) → operationalExpenses collection
2 Retrieve the new expense doc ID Query operationalExpenses where supplierInvoiceId == invoiceId (because recordExpense() returns void)
3 Process payment — hits ledger and deducts balance financeStore.processExpensePayment(expenseId, processedBy, paymentData)
4 Update invoice record to PAYMENT_PROCESSED procurementStore.updateSupplierInvoice(id, { status, operationalExpenseId, paymentMethod, paymentReference, paymentProcessedAt })

⚖ 3-Way Invoice Matching

Match Algorithm — computeInvoiceMatch()

Pure function in procurementStore — no Firestore calls:

function computeInvoiceMatch(invoiceTotal: number, expectedAmount: number) {
  const matchVariance        = invoiceTotal - expectedAmount
  const matchVariancePercent = expectedAmount > 0
    ? Math.abs(matchVariance / expectedAmount * 100)
    : 0

  let matchStatus: MatchStatus
  if      (matchVariancePercent === 0)   matchStatus = 'MATCHED'
  else if (matchVariancePercent <= 10)  matchStatus = 'VARIANCE_WITHIN_THRESHOLD'
  else                                    matchStatus = 'VARIANCE_EXCEEDED'

  return { matchVariance, matchVariancePercent, matchStatus }
}
matchStatusConditionUIOverride Required?
MATCHEDVariance = 0%MatchedNo — auto-approvable
VARIANCE_WITHIN_THRESHOLD0% < variance ≤ 10%Minor VarianceNo — can approve directly
VARIANCE_EXCEEDEDVariance > 10%VarianceYes — min 10-char reason required
OVERRIDE_APPROVEDWas EXCEEDED, override givenOverrideN/A — already overridden

expectedAmount Formula

// Computed from confirmed GRN items:
expectedAmount = grn.items
  .filter(item => item.qtyReceived > 0)
  .reduce((sum, item) => sum + item.qtyReceived * item.unitCostPrice, 0)

🔢 Auto-Numbering System

All document numbers are generated using Firestore transactions on systemCounters — atomic and collision-safe. Sequences reset annually.

Document TypeFormatExampleCounter Doc
Purchase RequisitionPR-YYYY-NNNNPR-2026-0001systemCounters/prNumbers
Purchase OrderPO-YYYY-NNNNPO-2026-0042systemCounters/poNumbers
Goods Receipt NoteGRN-YYYY-NNNNGRN-2026-0007systemCounters/grnNumbers
 
// Pattern used in all three generators:
const newSeq = await runTransaction(db, async (tx) => {
  const snap = await tx.get(counterRef)
  const seq = snap.exists() && snap.data().currentYear === year
    ? snap.data().lastSequence + 1
    : 1                    // new year = reset to 1
  tx.set(counterRef, { currentYear: year, lastSequence: seq, lastUpdatedAt: serverTimestamp() })
  return seq
})
return `PR-${year}-${String(newSeq).padStart(4, '0')}`

💰 Finance Module Integration

✅ Zero new collections. Procurement payments write into the existing operationalExpenses collection via useFinanceStore. The Finance module's updateLedger() function handles all balance calculations automatically.
